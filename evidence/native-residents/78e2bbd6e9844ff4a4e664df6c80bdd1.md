## Concrete interface

New subcommand added beside the existing ones:

```sh
python3 projects/blackout/blackout.py plan /path/to/surviving-archive /path/to/source.manifest.json
```

Argument order (`root`, `manifest`) matches `create` and `verify`: the first
argument is the surviving archive directory to scan, the second is the trusted
manifest to compare against. The printed JSON is deterministic: every list is
lexicographically sorted, JSON keys are emitted with `sort_keys=True`, and no
timestamp, random value, or host path is included (the manifest and archive
must be identical to reproduce byte-identical stdout).

Output fields preserve the `verify` contract and add the plan:

- `ok` (`bool`), `missing`, `changed`, `extra`, `matched` (`int`): identical
  to `verify`.
- `restores`: one entry per `missing`/`changed` target, sorted by `target`:
  `target`, `status` (`missing` or `changed`), `candidates` (sorted paths),
  `recoverable` (`len(candidates) > 0`), `ambiguous` (`len(candidates) > 1`).
- `ambiguous`: sorted targets needing an explicit human choice.
- `unrecoverable`: sorted targets with no byte-identical surviving source.

Candidate rule: a candidate is any surviving regular file whose `size` and
`sha256` are byte-identical to the expected manifest entry for that target.
The pool is every file in the surviving archive, so a renamed file (`extra`
with the bytes of a `missing` target) and a `matched` file whose bytes are
duplicated elsewhere are both listable candidates. A `changed` target's own
current bytes never match its expected entry, so it cannot be its own
candidate; the target path is also explicitly excluded. One surviving file
may serve several targets that share the same expected bytes (copying is
non-destructive, so sharing is allowed); each target is still judged on its
own `ambiguous` flag.

Read-only and boundary guarantees, each covered by tests:

- `plan` never copies, renames, overwrites, or deletes; it only scans with the
  existing descriptor-relative `inventory`/`load_manifest` paths, so symlinks
  (including root and manifest components), devices, sockets, FIFOs,
  nonportable names, `..` components, malformed manifests, and changed-during-scan
  inputs still fail with exit **2** and leave the archive untouched.
- Ambiguous duplicate-content choices are surfaced, never resolved: every
  matching surviving file is listed in `candidates` and `ambiguous` is true.
  The plan never silently chooses, executes a restore/rename/overwrite, or
  deletes `extra` files.
- Exit codes follow `verify`: **0** only when `ok` is true (no missing,
  changed, or extra); **1** when the plan describes any mismatch (including
  restorable, ambiguous, unrecoverable, or extra-only); **2** when unsafe
  input, a malformed manifest, or an I/O error (including closed stdout)
  prevented planning. A closed-stdout interruption exits **2** and leaves the
  archive and manifest byte-identical; re-run `plan`.
- This is a quiescent-snapshot comparison, not a transactional or hostile-writer
  snapshot, and not an authenticated or live-recovery claim. Exact-path
  matching is preserved: case-only or NFC/NFD spelling differences are still
  `missing`/`extra`, though the renamed bytes may appear as a byte-identical
  candidate for the original target. The manifest is the trusted baseline.
