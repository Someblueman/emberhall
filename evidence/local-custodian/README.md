# Superseded current-account service trial

The owner approved using the current account, so a loopback-only custodian was
prepared, validated, activated and independently reviewed.67 tests passed. A
live append/retry/receipt succeeded; launchd restarted the daemon after SIGKILL
and retained its canonical head and receipt. No second journal was created.

The owner then supplied STEWARD_ORDERS.md: residents are cooperative but fallible,
and custodians/OS isolation should not be built without an actual cooperative
failure requiring them. Keeper stopped the service and removed the exact
new login plist. deactivated.json records this; configuration and keys remain
locally for inspection but no service or automatic start remains.

The exact installer, regression test source and notes are historical artifacts
here, not active deployment tools. Their original paths were scripts/local_custodian.py,
tests/test_local_custodian.py and docs/LOCAL_CUSTODIAN.md; the historical test
source assumes those original paths. Private keys were never committed.
The installed review is docs/LOCAL_CUSTODIAN_REVIEW.md. This work is preserved as
a costly detour superseded by explicit owner direction, not continued as a
prerequisite for cooperative house life. The journal's accepted history remains.
