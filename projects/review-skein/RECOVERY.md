# Skein recovery and honest comparison

When a review packet travels across an air gap — on a USB stick, in an archive,
or attached to a message — files can be truncated, omitted to save space, or
left with temporary artifacts after an interrupted write. `recovery.py`
diagnoses and rebuilds damaged packets without touching the original directory,
and `comparison.py` measures how Skein's zero-service workflow compares against
raw `git bundle`, Gerrit and Radicle.

## Why four of the five packet files are replaceable

A Skein packet directory contains five files:

1. `changes.bundle` — a full, cloneable Git bundle carrying `refs/heads/skein-base`
   and `refs/heads/skein-head`.
2. `packet.json` — the version-1 manifest (`base` and `head` ref names and commit
   IDs, plus per-file line counts).
3. `anchors.json` — the exact `old` and `new` line table derived from the two
   commits.
4. `review.html` — the static escaped side-by-side diff derived from the two
   commits.
5. `comments.json` — the version-2 human review comments and resolution states.

Because `packet.json`, `anchors.json` and `review.html` are deterministic
functions of the two commits in `changes.bundle`, any of those three files can
be regenerated byte-for-byte from `changes.bundle`. Conversely, if
`changes.bundle` was omitted to save space (as in
`projects/review-skein/sample/milestone-2`), it can be regenerated from any
local Git repository that still holds the `base` and `head` commit objects, even
if branches in that repository have since moved forward.

`comments.json` is the only file that holds human-authored state not present in
Git history. Recovery preserves valid version-2 comments verbatim, upgrades
legacy version-1 comments, and — when explicitly requested with
`--salvage-comments` — reanchors or converts drifted comments into explicit
`orphan` records with `rebased_from` provenance instead of silently dropping
them.

Valid version-2 JSON is `intact_v2` even with different whitespace, key order,
Unicode escaping or CRLF line endings. Formatting is not corruption: `diagnose`
reports such a packet healthy when the other members pass, and `rebuild` copies
the original UTF-8 comment bytes without canonicalizing, reordering or changing
resolution/provenance. This also applies when rebuilding missing derived files.

## Diagnose a packet read-only

```sh
python3 projects/review-skein/recovery.py diagnose /path/to/packet
python3 projects/review-skein/recovery.py diagnose /path/to/packet --repo /path/to/worktree --json
```

`diagnose` never writes to the packet or repository. It checks:

- whether any of the five canonical files are missing or symlinks;
- whether leftover atomic temporary files (`.comments-*`, `*.tmp`,
  `bundle-source.git`) remain in the directory;
- whether `changes.bundle` clones and passes `git bundle verify` in an isolated
  temporary directory, and whether its `refs/heads/skein-base` and
  `refs/heads/skein-head` commits match `packet.json`;
- whether `packet.json`, `anchors.json` and `review.html` match a fresh
  deterministic export of those commits byte-for-byte;
- whether `comments.json` is valid version 2 (`intact_v2`), legacy version 1
  (`legacy_v1`), salvageable (`needs_salvage`), or unreadable (`corrupted`).

Exit codes:

- `0` — `healthy`: all five files are present and verified, the three derived
  files match the deterministic export, comments are valid v2 (any accepted JSON
  formatting), and no temporary files remain.
- `1` — `recoverable`: one or more derived files are missing or corrupted,
  `comments.json` is version 1 or needs anchor/ID salvage, or leftover temporary
  files are present, and a valid Git object source (`changes.bundle` or
  `--repo`) is available.
- `2` — `unrecoverable`: neither `changes.bundle` nor `--repo` can supply the
  commits, `packet.json` and `changes.bundle` disagree on commit IDs, or the
  packet path is not a regular directory.

For example, the repository's committed bundle-less sample can be checked
against the repository itself:

```sh
python3 projects/review-skein/recovery.py diagnose \
  projects/review-skein/sample/milestone-2 --repo . --json
```

## Rebuild a damaged or bundle-less packet

`rebuild` always writes to a **new** output directory so the damaged packet is
preserved as evidence:

```sh
# Rebuild missing or corrupted review.html / anchors.json from changes.bundle:
python3 projects/review-skein/recovery.py rebuild \
  /path/to/damaged-packet /path/to/rebuilt-packet

# Rebuild when packet.json was also lost, supplying the original ref labels:
python3 projects/review-skein/recovery.py rebuild \
  /path/to/damaged-packet /path/to/rebuilt-packet \
  --base-ref base --head-ref feature

# Re-attach changes.bundle to a lightweight packet from a local Git worktree:
python3 projects/review-skein/recovery.py rebuild \
  projects/review-skein/sample/milestone-2 /tmp/rebuilt-sample --repo .
```

Before publishing the new directory, `rebuild` verifies the reconstructed packet
with `skein.py verify` and checks `review.html` with `probe.py audit`.

If `packet.json` and `changes.bundle` name different commits, `rebuild` refuses
with exit code `2` rather than guessing which commit is authoritative. Passing
`--trust-bundle --salvage-comments` explicitly rebuilds from the bundle's
commits and reanchors or orphans the comments against the bundle's diff.

## Salvage mismatched, version-1 or duplicate-ID comments

If a `comments.json` file (or an interrupted `.comments-*` temporary file) has
legacy version-1 records, duplicate comment IDs from a manual edit, or anchors
whose line numbers or commits drifted:

```sh
python3 projects/review-skein/recovery.py salvage-comments \
  /path/to/damaged-comments.json /path/to/target-packet \
  --output /path/to/salvaged-comments.json
```

Or replace `comments.json` atomically inside the target packet:

```sh
python3 projects/review-skein/recovery.py salvage-comments \
  /path/to/damaged-comments.json /path/to/target-packet --in-place
```

What `salvage-comments` does:

1. **Upgrades version-1 comments** to version 2 with `resolution: "open"`.
2. **Preserves exact anchors** that match the target packet's `anchors.json`.
3. **Reanchors uniquely moved lines** on the same file path and side, recording
   the original anchor in `rebased_from`.
4. **Converts missing or ambiguous anchors into explicit orphans** (`state:
   "orphan"`) with `rebased_from` and a specific `orphan_reason` — never
   dropping a comment or guessing across duplicate lines.
5. **Splits colliding IDs deterministically** into `<id>--divergent-<digest>`
   variants when two records share an ID with different content, and collapses
   byte-identical duplicates.

## Clean leftover temporary files

If a process was killed during an atomic comment update, inspect and remove
leftover `.comments-*` or `*.tmp` files without touching the five canonical
packet members:

```sh
python3 projects/review-skein/recovery.py clean-temp /path/to/packet
python3 projects/review-skein/recovery.py clean-temp /path/to/packet --apply
```

## Measured comparison: Skein vs `git bundle`, Gerrit and Radicle

Milestone 4 asks whether zero-service packet exchange is genuinely easier than
raw `git bundle`, Gerrit or Radicle for this case. Run the live measurement on a
fresh temporary two-repository fixture:

```sh
python3 projects/review-skein/comparison.py measure --format markdown
python3 projects/review-skein/comparison.py measure --format json
```

The harness creates an author repository (`base` -> `feature`), clones the
bundle into an isolated reviewer repository, applies two independent reviewers'
notes (1 shared comment resolved by Reviewer 1, 4 line comments, and 1 colliding
same-ID comment pair), commits a revised patch `feature-v2` (where 1 commented
line is unchanged, 1 shifts down by 3 lines, 1 is rewritten, and 1 is a
duplicate `return None` line that shifts), and deletes `review.html` and
`anchors.json` from a packet copy to test recovery.

### Measured results on the fixture

Bytes count **two complete reviewer returns at `feature` v1, after annotations
and before merge**, using the same basis for both workflows. Each raw return
contains `changes.bundle`, `review.patch`, and `notes.json`; each Skein return
contains all five packet files, including that reviewer's `comments.json`.
Shared files are counted once per return. The author baseline, working clones,
merged/revised/rebuilt outputs, transport and filesystem overhead are excluded.

Raw `notes.json` is the full ordered array of that reviewer's static notes,
including shared notes, their resolution and both colliding-ID variants across
the returns. Each record retains `id`, `side`, `line`, `text`, `resolution`, and
`body`; this single-file fixture refers to `src/service.py`. Serialization is
UTF-8 JSON with sorted object keys, two-space indentation, unescaped Unicode,
and one trailing LF. No records are discarded before counting. JSON output
exposes `reviewer_exchange_bytes` and every `reviewer_artifacts` path/size.

| Metric | Raw `git bundle` + static notes | Review Skein (`skein` + `exchange` + `recovery`) |
| --- | ---: | ---: |
| Two complete reviewer returns (bytes) | 3,701 B | 22,773 B |
| Extra tools beyond `git` | 0 | 1 (Python 3.10+ stdlib) |
| CLI commands executed in scenario | 5 | 13 |
| Same-ID merge collisions lost/conflicted | 1 | 0 (2 divergent variants kept) |
| Accurately anchored comments on `feature-v2` | 3 | 5 |
| Explicit orphans with `rebased_from` provenance | 0 | 2 |
| **Silent mis-anchored comments on `feature-v2`** | **3** | **0** |
| Byte-exact rebuild of deleted `review.html` + `anchors.json` | n/a | `True` |

On this run the raw total is 1,530 B of bundles + 744 B of patches + **1,427 B
of notes** (717 B and 710 B). The Skein total is 1,548 B of bundles + 1,062 B
of manifests + 5,856 B of anchors + 10,910 B of HTML + 3,397 B of comments.
The earlier 1,137 B vs 10,165 B / roughly 9× claim is withdrawn: it omitted raw
notes and measured Skein before both reviewers' annotations. Bundle sizes may
vary with Git versions; rerun the fixture and inspect the per-file breakdown.
These results describe this fixture and its naive static-note merge, not a
general ease-of-use, browser or screen-reader trial. Gerrit and Radicle are not
executed or benchmarked here; the retained capability matrix is an overview.

### Capability matrix across all four tools

| System | Server / daemon required | Air-gap / sneakernet | Rebase reanchoring & orphans | Cryptographic identity | Central CI & ACLs |
| --- | --- | --- | --- | --- | --- |
| Review Skein (stdlib CLI + static packet) | No | Yes | Yes | No | No |
| Raw `git bundle` + `git diff/range-diff` + static notes | No | Yes | No | No | No |
| Gerrit Code Review | Yes | No | Yes | Yes | Yes |
| Radicle (peer-to-peer local-first forge) | No | No | No | Yes | No |

### Honest trade-offs: when to use something else

- **When raw `git bundle` is better:** if you only need to carry commits across
  an air gap or read a single patch in a terminal without tracking line comments
  across multiple reviewers or revised commits, raw `git bundle` + `git diff` is
  smaller in this fixture's two complete returns (`3,701 B` vs `22,773 B`, with
  all notes included), omitting the standalone HTML page and JSON anchor table.
- **Where Review Skein helps in this fixture:** the naive raw line-number merge
  attaches 3 of the 5 retained head-side comments to the wrong lines after a
  3-line insertion and rewrite, and collide on duplicate comment IDs. Skein
  merges both reviewers' notes commutatively, keeps colliding IDs as distinct
  `--divergent-<digest>` records, moves uniquely matching lines to their new
  line numbers, marks rewritten or ambiguous duplicate lines as explicit
  `orphan` comments with `rebased_from` history, and rebuilds lost HTML/anchor
  files byte-for-byte from `changes.bundle`.
- **When Gerrit is better:** when participants share network access to a server
  and need authenticated accounts, branch permissions, automated CI gatekeeping,
  and browser-hosted patchset comparison. Skein has no server, no accounts and
  no CI runner.
- **When Radicle is better:** when a distributed team wants cryptographic
  peer-to-peer identity (Ed25519 DIDs and signed collaborative objects) synced
  over a gossip network via `rad-node`. Skein hashes bind bytes, not people; it
  does not sign comments or verify reviewer identity.

## Honest boundary of recovery

- If **both** `changes.bundle` and the original Git repository objects are lost,
  `review.html` and `anchors.json` cannot reconstruct the missing Git history.
- If `comments.json` is truncated into unparseable non-JSON bytes and no
  `.comments-*` temporary file or reviewer copy survives, `recovery.py` refuses
  rather than fabricating comment records.
- Rebuilding a packet proves that `review.html`, `anchors.json` and
  `packet.json` match the Git objects in `changes.bundle`; it does not prove who
  authored the commits or comments.
