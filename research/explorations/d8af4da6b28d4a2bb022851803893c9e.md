### 5. `ZoneRule`: Zero-Dependency Python `zoneinfo` RFC 5545 `RRULE`/`RSet` Engine — **SELECTED (`zonerule-dst-safe-rrule`)**

#### Closest Existing Tools & Libraries Read
1. **`python-dateutil` (`dateutil.rrule`)** — `https://dateutil.readthedocs.io/en/stable/rrule.html`
   - De facto RFC 5545 engine in Python, but:
     - **Open Issue `#938`** (`https://github.com/dateutil/dateutil/issues/938`, `@salty-horse`): stores `UNTIL` as `datetime` rather than preserving `DATE` vs `DATE-TIME`, miscomputing `.between()` and round-trip strings for Google/Microsoft Calendar `UNTIL=20190720` rules.
     - **Open Issue `#1611`** (`https://github.com/dateutil/dateutil/issues/1611`, `@vera-rubin`): `rrulestr` silently drops `TZID` from `DTSTART` when `VALUE=DATE-TIME` follows it.
     - **Open Issue `#851`** (`https://github.com/dateutil/dateutil/issues/851`, `@raguiar2`) and Stack Overflow `53997143`: confusing `ValueError: RRULE UNTIL values must be specified in UTC when DTSTART is timezone-aware`.
     - **Open Issue `#654`** (`https://github.com/dateutil/dateutil/issues/654`, `@jelly`): `.between()` iterates from `dtstart` over decades instead of seeking/bounding.
     - **DST / invalid datetimes** (`#88`, `#102`, Waracle engineering blog): lacks explicit PEP 495 `fold` and spring-forward gap policies, can emit invalid/non-existent local datetimes or shift across DST, and relies on legacy `six` + `dateutil.tz`.
2. **`python-dateutil-rs`** — `https://pypi.org/project/python-dateutil-rs/`
   - Compiled Rust/PyO3 drop-in clone of `python-dateutil` 2.9.0; improves speed but requires compiled wheels and intentionally preserves `dateutil` semantics and API quirks.
3. **`recurring-ical-events`** — `https://github.com/niccokunzmann/python-recurring-ical-events`
   - Expands full `.ics` `VEVENT`/`VTODO` components and works with `zoneinfo`, but pulls in `icalendar`, `python-dateutil`, and `x-wr-timezone` (wrapping `dateutil.rrule` rather than replacing it).
4. **`whenever`** — `https://pypi.org/project/whenever/`
   - Modern DST-safe datetime library for Python, but has no RFC 5545 `RRULE`/`RSet` parser or recurrence expander (`https://github.com/ariebovenberg/whenever/issues/365`).
5. **`rrule-boundary-kit`** — `https://github.com/taroyamada3173-sys/rrule-boundary-kit`
   - A 12-fixture JSON boundary test comparator, not an `RRULE` library.

#### What `ZoneRule` Does Differently
- **Zero external dependencies:** Pure Python 3.11+ standard library (`datetime`, `zoneinfo`, `calendar`, `dataclasses`).
- **Explicit PEP 495 `fold` & DST gap policies:** Separates calendar wall-clock frequencies (`DAILY`, `WEEKLY`, `MONTHLY`, `YEARLY`) from elapsed-UTC frequencies (`HOURLY`, `MINUTELY`, `SECONDLY`), with explicit `gap` (`skip`, `shift_forward`, `shift_backward`, `error`) and `fold` (`first`, `second`, `both`, `error`) policies.
- **Fixes `UNTIL` & `TZID` round-trips:** Supports inclusive `DATE` `UNTIL` (`UNTIL=20190720`) alongside timezone-aware `DTSTART`, preserves `TZID` across `parse`/`format` round-trips regardless of `TZID`/`VALUE` parameter ordering, and optimizes bounded `.between()` queries.
- **Occurrence provenance (`explain()`) + importing CLI:** Explains why any candidate timestamp was emitted, shifted, or excluded (`EXDATE`, `UNTIL`, DST gap/fold), and ships with a real importing CLI (`python3 -m zonerule`) and calendar-audit script (`examples/ics_schedule_audit.py`).
