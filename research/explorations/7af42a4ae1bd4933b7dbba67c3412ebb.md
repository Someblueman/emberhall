## Adaptive privacy as a language feature

The need is real: an analyst may choose both the next query and its privacy
parameters from earlier outputs. [Whitehouse et al. (2023)](https://proceedings.mlr.press/v202/whitehouse23a.html)
address this mathematically. However, [OpenDP's privacy-filter guide](https://docs.opendp.org/en/stable/api/user-guide/combinators/privacy-filters.html)
already constructs a filter over fully adaptive composition and shows it refusing
queries beyond a budget. A new syntax around this behavior is not a new capability.

[Jazz](https://pleiad.cl/papers/2023/toroAl-toplas2023.pdf), sections 1, 9.1 and
the conclusion, already supplies contextual linear types, higher-order privacy
programming, a prototype typechecker and case studies. I did not establish that
a proposed information-tier effect system would accept a useful program that
these languages and ordinary encapsulated OpenDP code cannot adequately express.

[Taylor, Vippathalla and Coon (2026)](https://arxiv.org/html/2611.03130v1),
introduction and section 5, distinguish specification, mechanism and realized
information. Their open questions concern useful intermediate information
summaries and optimal procedures. These are potential mathematical research
directions, not evidence that merely tracking information access in a type
solves privacy: stopping based on outputs itself needs a privacy argument.

## Bounded-memory stream programming

[Dominguez's concrete comparison](https://www.tweag.io/blog/2017-10-05-streaming2/)
describes input retention, lookahead, leftovers and accidental repeated stream
consumption. [Stream Types (2024)](https://web.cs.ucdavis.edu/~cdstanford/doc/2024/PLDI24.pdf)
already gives sequential/parallel stream types and Delta. I read the motivation,
buffering footnote, historical-state discussion and future work. Its explicit
buffering limitation initially looked like a promising language boundary.

The decisive newer predecessor is [Cutler's 2026 dissertation](https://cutler.pl/assets/dissertation.pdf):
abstract, introduction, and sections 7.1–7.3. It introduces **Yoink**, with an
ordered type system, pull graphs and a compiler targeting bounded-space stream
processing. Inventing those features again would repeat existing work.
The thesis explicitly leaves semantic soundness and compiler correctness proofs
open; I did not prove them, check all rules, or verify their current publication
status. They remain named leads, not accepted new results or a new language idea.

I also opened the [Delta repository](https://github.com/alpha-convert/delta)
and [Functional Meaning for Parallel Streaming](https://arxiv.org/html/2504.02975v1),
including its implementation discussion. Neither repository inspection nor
reading a semantics is execution evidence. Deterministic incremental processing
alone is already a developed language idea, not this round's contribution.

## Offline collaboration with explicit safety rules

[LoRe's paper](https://drops.dagstuhl.de/storage/00lipics/lipics-vol263-ecoop2023/LIPIcs.ECOOP.2023.12/LIPIcs.ECOOP.2023.12.pdf)
already combines reactive data, application invariants and compiler-selected
coordination. Its [repository](https://github.com/stg-tud/LoRe) points to the
[Bismuth module](https://github.com/stg-tud/Bismuth/tree/main/Modules/Lore);
the module directory loaded, but that is not a current functionality test.
[VeriFx's primary abstract](https://arxiv.org/abs/2207.02502) describes verified
replicated data types and compilation to ordinary implementation languages.

[No-Op (2025)](https://drops.dagstuhl.de/storage/00lipics/lipics-vol333-ecoop2025/LIPIcs.ECOOP.2025.4/LIPIcs.ECOOP.2025.4.pdf),
introduction, worked conflict example and section 6.1, already models explicit
conflict policies and distinguishes reversible updates from operations requiring
coordination. A language that calls discarded operations provisional would need
more than renamed versions of these mechanisms. Likewise the updated
[choreographic-failure paper](https://arxiv.org/abs/1712.05465) already states
omission-recovery strategies and delivery analyses; I read its abstract only.
