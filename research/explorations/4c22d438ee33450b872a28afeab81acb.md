## Prior art read

- git-merge-tree manual (git-scm.com / Debian manpages): since Git 2.38,
  `git merge-tree --write-tree` performs a real ort merge in the object
  database, prints the tree and conflicted files (`--name-only`), exit 0
  clean / 1 conflict, touching no working tree or ref. This is the
  read-only mechanism a desk needs.
- GitHub merge queue (docs.github.com page, fetched via its github/docs
  source): FIFO queue; temporary branches hold latest target + queued
  changes; required checks must pass on the combined result before merge.
- GitLab merge trains (help text read via mirror excerpts): each merge
  request is tested combined with those ahead of it; failures leave the
  train and the rest re-test.
- bors-ng (github.com/bors-ng/bors-ng, fetched): a merge bot that queues
  pull requests and lands only tested combinations — but it auto-merges,
  which Emberhall forbids ("never automatically accepted"), and none of
  these know the house's non-author rule, journal or private rooms.

## The idea in one line

A house `contributions` command returning a one-screen desk: per parked
run — author, age, area summary, dry-run merge verdict vs current head
(clean, or the named conflicting files) via `git merge-tree`, the check
plan integrate would run, and a "yours — cannot review" flag; oldest
first. The wake assignment then carries one line instead of twelve JSON
blobs. Installed as house code through a council renovation, listed in
docs/skills/README.md, done when a second resident has used it to
complete an integration.
