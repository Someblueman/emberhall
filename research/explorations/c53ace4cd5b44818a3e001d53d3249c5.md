## Compare private spreadsheets without uploading them — do not shelve

[Krnson's question](https://www.reddit.com/r/excel/comments/1qhfheg/how_to_compare_two_workbooks/)
asks how to compare two building-location lists. Another participant describes
maintaining a comparison template manually. The original asker marks a Power
Query answer verified: the thread itself supplies an existing solution, not
only an unanswered request.

Opened the [Bitmetric comparison tool's documentation](https://github.com/bitmetric-bv/local-file-compare)
and inspected relevant [public source](https://raw.githubusercontent.com/bitmetric-bv/local-file-compare/main/index.html):
composite keys, column mapping, value comparisons, export, and explicit duplicate
warnings already exist. Source inspection narrows the duplicate claim: it keeps
the last row for a repeated key in the second file and warns that results may
be incomplete. Its number parser uses permissive numeric conversion; this was
not a correctness audit or an endorsement for arbitrary private data. It also
fetches a public repository timestamp, so local file processing is not the same
claim as making no network requests at all.

Opened [cligc's actual comparison page and limits](https://www.cligc.com/compare-spreadsheets):
it documents excluding duplicate/incomplete keys, separate uncompared exports,
text comparison rules, cached formula results and input bounds. Read a
[duplicate-key guide](https://spreadsheetcomparison.com/guides/duplicate-keys/)
which distinguishes repeated entities from repeated records and warns against
inventing identity from mutable fields. Also opened
[DiffSheets](https://www.diffsheets.com/en), which documents local comparison
by position, key or sequence alignment. These are overlapping alternatives;
their documentation is not an independently observed runtime result.

No two-site request for a particular missing behavior survived this comparison.
A new generic private table comparator would repeat documented capabilities.

## Show what shell quoting does to arguments — do not shelve

[vfclists](https://unix.stackexchange.com/questions/787551/is-there-a-tool-that-can-print-out-a-bash-script-with-the-variables-substituted)
asks: "Is there a tool that can show how the script with the substituted variables will look like?"
The discussion distinguishes simple substitutions from values that require
execution. [Oreo's firsthand account](https://oreo.life/en/blog/2025-03-11-bash-expansion-when-quoting-variables-backfires/)
describes writing an argument-printing helper and investigating Bash's source
to understand quotes carried inside a variable. This establishes real diagnostic
work, not demand for a particular new page.

Opened [Command Line Anatomy](https://robotsfirst.org/tool/cli-argv-parser-visualizer/):
it already documents an offline, nonexecuting argument display with variable,
quote, glob and pipe examples. Its environment and file list are fixed demos;
it is explicitly a simplified teaching model. Read selected passages in sections 2.1, 4.2 and 6 of
the [Smoosh paper](https://cs.pomona.edu/~michael/papers/smoosh_sub2020.pdf),
including the Shtepper's expansion states, simulated environment and single-path
limit. Opened its [repository and installation documentation](https://github.com/mgree/smoosh).
The hosted Shtepper address was inaccessible to fetch; that is not evidence
that its server is down or that the tool has no users.

Also opened [ShellCheck](https://www.shellcheck.net/),
[explainshell](https://explainshell.com/) and the
[Bash parser playground](https://vorpaljs.github.io/bash-parser-playground/).
These respectively address diagnostics, argument help text and syntax trees;
they are not interchangeable with expansion traces. Nevertheless, direct
visualization already exists. Editable demo state might be a convenience, but
this screen found no demonstrated unmet request that justifies another partial
shell interpreter. Do not treat a lexical word display as actual runtime arguments.

## Explain calendar recurrence across clock changes — do not shelve

Opened [plebcity's MagicMirror report](https://github.com/MagicMirrorOrg/MagicMirror/issues/3797)
and its resolution: the reporter observed recurring events one hour late,
provided an example and developed a repair; the issue was closed as completed
on 30 June 2025. Opened
[g00fy's question and discussion](https://stackoverflow.com/questions/12504247/how-to-handle-dst-and-tz-in-recurring-events):
the author needs recurring local hours to survive changing offsets. This is an
older, concrete programming problem, not a current request for a new calendar app.

Read [rrule.js's timezone documentation](https://github.com/jkbrzt/rrule#important-use-utc-dates),
which explains its unusual representation of local/floating values, and opened
its [demo](https://jkbrzt.github.io/rrule/). Opened
[RunLocalTools' calendar editor, privacy and limitations](https://runlocaltools.online/ics-modifier/):
it documents local recurrence previews, zone conversion versus zone relabelling,
clock-change warnings, exceptions, and limits on complex rules and custom zones.
[ICS Viewer](https://icsviewer.com/) documents recurrence exceptions, modified
occurrences and timezone definitions without importing into an account.
[Nobuf](https://www.nobuf.com/tools/schedule-expression) documents local schedule
explanations, timezone previews and comparisons, with platform-specific limits.

A small visual explanation could still help someone, but the opened requests
ask for correct scheduling behavior and fixes to specific implementations.
I found no supported additional job beyond these existing previews and guidance.
Do not turn a historical fixed bug into a claim of a currently missing tool.
