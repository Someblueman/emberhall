## Vetted candidate: `two-deletion-codes`

- **ID / Scale / Field / Worth / For:** `two-deletion-codes` · `small` ·
  `mathematics` · `enabling` · `field`
- **Problem:** Determine tighter bounds and verified codebooks for binary
  two-deletion-correcting codes of length `n >= 12` (`2dc.4096`, `2dc.8192`,
  and `n = 13..16`), extending OEIS `A057591`.

### Sources read via built-in search and verbatim anchors

| Source | Verified reading and role in brief |
| --- | --- |
| [OEIS A057591](https://oeis.org/A057591) | Lists exact terms only for `n = 1..11`: `1, 1, 2, 2, 2, 4, 5, 7, 11, 16, 24`. Quotes: *"Maximal size of binary code of length n that corrects 2 deletions."* and *"Pablo San Segundo and Jorge Artieda showed that a(11) = 24, Dec 04 2015."* |
| [Sloane's Challenge Graphs](https://oeis.org/doc/graphs.html) | Supplies DIMACS benchmark graphs (`2dc.2048`, `2dc.4096`) without a bundled solver. Quote: *"The graphs are specified in the DIMACS format. For a graph with say 64 nodes and 543 edges, the first line of the file would read: p edge 64 543."* |
| [Weindel & Heckel (arXiv:2504.00613)](https://arxiv.org/abs/2504.00613) | Adapts FunSearch to deletion codes; improves `s = 2` lower bounds at `n = 12` (to `34`), `n = 13` (to `50`), and `n = 16`. Quotes: *"Finding deletion-correcting codes of maximum size has been an open problem for over 70 years, even for a single deletion."* and *"For multiple deletions and quaternary edit codes, the discovered functions improve on prior explicit, search-based, and neural constructions but remain empirical heuristics without new theoretical insights."* |
| [OpenReview forum (TMLR)](https://openreview.net/forum?id=qZ69Ozpo6v) | Confirms TMLR publication and the `n = 12, 13, 16` two-deletion lower-bound advances (`34` at `n = 12`, `50` at `n = 13`). |
| [MLI-lab/DistributedFunSearch](https://github.com/MLI-lab/DistributedFunSearch) | Public repository under `src/disfun/specifications/ECC/`. Quote: *"Our implementation includes an example application for discovering large deletion correcting codes."* Requires LLM/RabbitMQ sampling and produces greedy heuristics without upper bounds or exact branch-and-bound. |
| [Kulkarni & Kiyavash (arXiv:1211.3128)](https://arxiv.org/abs/1211.3128) | Models deletion codes as hypergraph matchings and derives non-asymptotic LP-dual upper bounds. Quote: *"The problem of finding the largest deletion correcting code is modeled as a matching problem on a hypergraph. This problem is formulated as an integer linear program. The upper bound is obtained by the construction of a feasible point for the dual of the linear programming relaxation of this integer linear program."* |
| [Nakasho et al. (arXiv:2309.14736)](https://arxiv.org/abs/2309.14736) | Proves single-deletion `n = 11` tight upper bound (`172`) via ILP constraints. Quote: *"In this paper, we discuss a method for calculating this upper bound by providing an integer linear programming solver with several linear constraints. As a new result, we obtained that the tight upper bound for the size of a single deletion error correcting code in dimension 11 is 172."* |
| [Brakensiek, Guruswami & Zbarsky (arXiv:1507.06175)](https://arxiv.org/abs/1507.06175) | Explicit $O(k^2 \log k \log n)$-redundancy $k$-deletion codes for asymptotic $n$, suboptimal at short block lengths `n = 12..16`. |

### Scope and honesty bounds

San Segundo and Artieda's December 2015 optimality proof of `a(11) = 24` on
`2dc.2048` required 16.4 days on an 18-core Xeon system using BBMCX, even
though their heuristic found size `24` in seconds. Therefore, this small-project
brief does **not** promise an exhaustive exact optimality proof for `n = 12`
(`2dc.4096`) within a few days. Instead, its `first_version` promises: (1) an
independent, zero-dependency Python verifier (`verify.py`) checking deletion
balls and upper-bound certificates from raw definitions; (2) a symmetry-reduced
(reversal + bit-complement) Rust packed-bitset solver reproducing exact
`A057591` optima for `n = 1..11` (including `2dc.2048 = 24`); and (3) computed
LP/clique-cover upper-bound certificates and orbit-seeded local/branch-and-bound
search codebooks for `n = 12..16`.
