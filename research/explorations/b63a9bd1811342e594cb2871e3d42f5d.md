## 2. Root-Cause Diagnosis in `house/`

Inspecting `house/record.py`, `house/mailbox.py`, `house/__main__.py`, `house/home.py`, `house/mailbox_jobs.py`, and `house/resident_actions.py` revealed **four compounding defects** that explain why every mailbox call degrades linearly with journal length (now 53,420+ events) and stalls past 120 seconds:

### Defect A: `mailbox.process()` Bypasses `Record._replay` on Every Command (`house/mailbox.py:172,202,211` & `house/__main__.py:191-201`)
On 21 November (at 28,700 events), `Record._replay` was added to `house/record.py:81-103` so the coordinator's persistent `self.record` would cache its last verified replay and apply only new commits.
However:
- In `house/mailbox.py:172`, `mailbox.process(record, ...)` calls `state, events, head = snapshot(record)` on the coordinator's persistent `record`.
- Then at `house/mailbox.py:202` (for `MUTATIONS`) and `house/mailbox.py:211` (for reads), `mailbox.process` calls `result = dispatch(args)` (`house.__main__.run(args)`) **without passing `record`**.
- The very first lines of `house/__main__.py:run(args)` (`lines 191-201`) execute:
  ```python
  def run(args: argparse.Namespace) -> object:
      record = Record(args.repo)
      ...
      state, events, head = record.read()
  ```
- Because `Record(args.repo)` is a brand-new `Record` instance with `_replay = None`, **every single mailbox request** ignores the coordinator's warm `self.record._replay`, spawns `git rev-list` and `git cat-file --batch` over **106,840+ Git objects** (53,420+ commits and 53,420+ blobs), verifies 106,840+ SHA-1 digests, parses 53,420+ JSON events, and runs `apply_event` 53,420+ times from event #1.

### Defect B: Mutations Replay Twice and `Record.read()` Deep-Copies All 53,420 Events Unconditionally (`house/__main__.py:201,215,373` & `house/record.py:103,161-178`)
- For any mutation (`wake`, `say`, `task`, `claim`, `finish`, `sleep`, `life`, `shelf`), `house/__main__.py:run(args)` first calls `record.read()` at line 201 on the temporary `Record` (cold replay #1 of 53,420 events), and then calls `record.append(...)` at line 215 or 373, which enters `with self.locked():` and calls `self.read()` again at `house/record.py:164` (deep-copying the entire state and 53,420-event list a second time).
- Furthermore, `Record.append()` (`house/record.py:174-177`) does not extend `self._replay` with the newly committed `(oid, next_state, event)`, and even when `self.record.read()` hits `_replay` on the coordinator's persistent `self.record` (called 10–15 times per `Coordinator.tick`), `house/record.py:103` unconditionally executes `copy.deepcopy(state), copy.deepcopy(events)` over all 53,420 event dictionaries even when the caller only reads `state` (`self.record.read()[0]`, used at 19 call sites across `house/home.py`, `house/source_delivery.py`, `house/mailbox_jobs.py`, `house/integrate.py`, and `house/resident_actions.py`) or only slices 20 events.

### Defect C: `Coordinator.tick()` Starves `mailbox.service()` Behind Synchronous Clones, Network I/O, and Sweeps (`house/home.py:1834-2143`)
- In `house/home.py`, `mailbox.service(self.record, self.private, run)` is called **only once per tick**, inside `self.reap()` (`line 1838`).
- Before returning to `reap()`, the single coordinator thread synchronously executes `resolve_completed_help()`, `renovate()`, `queue_review()`, the `for _ in range(total_limit):` admission loop (up to 5 run starts in one tick, each running `home_work.room()` -> `git clone` of the repository into `residents/RUN` and multiple `self.record.read()` calls), `deliver()` (`git ls-remote` / `git push` with 60s timeouts), `inbox.poll()` (`gh api`), and `housekeeping.sweep()` (removing up to 40 room clones).
- During a multi-run admission burst (such as `seq:53365..53379`, where 5 runs launched back-to-back) or slow network poll, `mailbox.service()` is not called for over 120 seconds, causing active residents' `.house-client` calls to time out.

### Defect D: Abandoned Timed-Out Read Requests Pile Up in `.house-mailbox/requests/` and Action Subprocesses Cold-Replay (`house/mailbox.py:261-313` & `house/mailbox_jobs.py:343-368`)
- When `.house-client` times out after 120 seconds (`house/mailbox.py:313`), the request file `<key>.json` remains in `.house-mailbox/requests/`. When the coordinator finally services that room, it still executes every abandoned read-only request (`read`, `digest`, `status`, `rules`, `lesson`, `lens`) before reaching the resident's newer request.
- In `house/mailbox_jobs.py:352`, every spawned action worker subprocess (`integrate --inspect`, `view`, `read-site`, `review-complete`) creates a fresh `Record(args.repo)` with no disk-cached replay checkpoint, cold-replaying all 53,420+ events in `resident_actions.execute()` (`house/resident_actions.py:114`) and again in `integrate.source()` (`house/integrate.py:45`).

## 3. Direct Reproduction in a Disposable House Fixture

Running a controlled benchmark against `house.mailbox.process` in a disposable `HouseCase` fixture with 42 journal events and an already-warm `case.record._replay` confirmed:
- **Current behavior:**
  - One `mailbox.process(case.record, ..., ["read", "--as", "alice", "--limit", "5"])` call invoked `apply_event` **43 times** (full replay from event #1 despite `0` new events).
  - One `mailbox.process(case.record, ..., ["say", "--as", "alice", "--request", "r-say-1", "hello"])` call invoked `apply_event` **44 times** (full replay from event #1 plus the new event).
- **Expected behavior after passing `record=record` into `house.__main__.run(args, record=record)` and updating `_replay` on `append`:**
  - Warm `read` invokes `apply_event` **0 times**.
  - Warm `say` invokes `apply_event` **1 time**.
