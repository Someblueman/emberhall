## Hear the Controls

Propose a native Mac terminal host and an importable bridge for participating
terminal applications. It runs a real shell, retains the ordinary terminal
display, and exposes the application's declared controls to VoiceOver.
It cannot infer reliable widgets from arbitrary character output.

The need is directly described by Fridux on r/Blind, miki123211 and Textual
author willm on Hacker News, and the Ratatui accessibility contributors.
These are four people across three sites; the canonical brief retains short
exact quotations. They establish a need, not endorsement of this design.

- [Ratatui discussion and Linux witness](https://github.com/ratatui/ratatui/issues/2610)
- [Blind user's experience](https://www.reddit.com/r/Blind/comments/w0zou1/is_textbased_user_interface_tui_screen_reader_the/)
- [Textual author and screen-reader user's discussion](https://news.ycombinator.com/item?id=41215679)
- [Bubble Tea request](https://github.com/charmbracelet/bubbletea/issues/780)

The closest implementations narrow the proposed contribution substantially.
[tui-a11y](https://docs.rs/crate/tui-a11y/latest) supplies real Linux integration
but explicitly leaves macOS unattempted. [Taria](https://y0sif.github.io/taria/)
supplies actionable trees for agents, not the native screen-reader host.
[Lector](https://github.com/n0ot/lector) already speaks terminal text and offers
review/table navigation. [FrankenTUI](https://docs.frankentui.com/a11y-i18n/a11y-tree)
documents semantic trees while deferring platform bridges.
[Chau7](https://chau7.sh/features/voiceover-support) carefully limits its current
native-accessibility claims. [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm)
demonstrates an existing real terminal engine and local-process view; reuse,
licensing and dependency admission must be settled before implementation.

The missing deliverable is native widget discovery and action round trips in
one real terminal window. [Apple's custom-control contract](https://developer.apple.com/documentation/appkit/custom-controls.md)
and [AccessKit tree updates](https://docs.rs/accesskit/latest/accesskit/struct.TreeUpdate.html)
provide existing semantics to reuse. No new universal terminal standard is
claimed. Focus, node lifetime and input routing are central risks.

Three-day stop gate: a non-author must operate an actual instrumented program
through VoiceOver, using access the house already has. A diagnostic tree dump
does not pass. Then extend beyond a single demonstration to reusable widgets
and independent app integrations. No Windows or remote-session promise.

## Shared Noise

Propose an importable library for a documented subset of neutron-data
reductions, carrying first-order covariance through reused measurements,
normalization, background subtraction, fixed windows and rebinning.
The contribution would be composability and usable scale, not new error theory.

[Heybrock, Wynen and Vaytet (2023)](https://journals.sagepub.com/doi/10.3233/JNR-220049)
derive covariance for selected workflows. Their example experiments do not
establish a large scientific effect in general. The accessible abstract of
[Heybrock's 2025 follow-up](https://journals.sagepub.com/doi/10.1177/10238166251313932)
describes the unknown-workflow limitation and provides fast upper bounds;
the full text was not available through the reader.

[Scipp](https://scipp.github.io/user-guide/computation.html) rejects unsupported
variance-bearing broadcasts. [ESSreduce](https://scipp.github.io/ess/reduce/user-guide/reduction-workflow-guidelines.html)
already specifies upper-bound handling as the default. This proposal must not
claim that existing workflows simply cannot run. [ScippUncertainty](https://scipp.github.io/scippuncertainty/user-guide/mc.html)
offers Monte Carlo propagation. [NeuNorm](https://neunorm.readthedocs.io/en/main/api.html)
explicitly documents correlations remaining after overlapping windows.

[gvar](https://gvar.readthedocs.io/en/latest/overview.html),
[Rocky Mountain Ellipse](https://pages.nist.gov/rmellipse-ipages/v0.5.1/autoapi/rmellipse/uobjects/index.html)
and [CoMet](https://www.comet-toolkit.org/) already handle correlated uncertainty
in important ways. They are required baselines, not dismissed predecessors.
The first gate must establish a concrete missing integration or scale benefit.

Checks: independent dense first-order covariance, repeated versus independent
sources, dimension order, masks, signed weights and overlapping windows.
An initial 100,000-event/128-output-bin workload has a one-GiB memory ceiling.
Runtime must be measured fairly, not assumed better. First-order validity and
unsupported operations remain explicit. No arbitrary-workflow guarantee.
Supplementary data at Zenodo could not be retrieved; the first gate can use
fully specified small cases without claiming a full experimental reanalysis.

## Other directions screened

- General deterministic asyncio simulation: [detangle](https://pypi.org/project/detangle/),
  [simloop](https://pypi.org/project/simloop/0.2.1/) and
  [frontrun](https://github.com/lucaswiman/frontrun) already cover the initial
  scheduling/replay proposal. No narrower need was established here.
- Accessible chart navigation: [Olli](https://umwelt-data.github.io/olli/using/),
  [Umwelt](https://umwelt-data.github.io/umwelt/using/viewer) and
  [MAIDR](https://maidr.ai/) overlap the initial proposal closely.
- Collaborative spreadsheets and Python reverse debuggers have substantial
  existing implementations; those broad leads were not developed into briefs.
  This is not a finding that those fields have no worthwhile remaining work.
