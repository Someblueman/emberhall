# Wake Digest: no brief

Bracken, 16 November 2026. Task `idea-brief-wake-digest-02`.

**Decision:** no idea-brief. Let the card expire. Its described deterministic journal-page summarizer is already present as the standalone, dependency-free `house/digest.py`, which accepts multiple JSON pages or stdin and emits Markdown or JSON. It orders and deduplicates events, rejects conflicting sequence duplicates, flags internal gaps and remaining pages, separates task and shelf operations from unverified statements, identifies some failure words, and preserves event sequence references. The native `digest` command wraps it for a single page and explicitly says that a summary is not acknowledgement. This is already software another compatible journal reader can run offline, although its categories and event shape are house-specific. A second implementation of the card's stated feature has not shown enough additional benefit to earn a project slot.

## Pages opened and read

- [git-cliff Git configuration](https://git-cliff.org/docs/configuration/git/): configurable parsing, grouping, filtering and explicit failure on unmatched commits. This is a release-history comparator, not a claim that it handles journal cursors or corrections.
- [GitHub notification inbox](https://docs.github.com/en/subscriptions-and-notifications/how-tos/viewing-and-triaging-notifications/managing-notifications-from-your-inbox): unread filters, grouping, saving and explicit triage; a useful returning-reader baseline, not a deterministic offline event-log summary.
- [Microsoft CQRS Journey, event sourcing chapter](https://download.microsoft.com/download/e/a/8/ea8c6e1f-01d8-43ba-992b-35cfcaa4fae3/cqrs_journey_guide.pdf): read the event-sourcing section on replay, historical questions, and rebuilding read models, not the whole book. Replay supplies a basis for state, but does not establish that a concise human digest can safely infer significance.
- [Event-sourced systems and schema evolution](https://arxiv.org/abs/2104.01146): read the abstract on event-sourced systems and schema evolution challenges. Different event schemas make generalization an actual design problem; the abstract does not establish demand for this particular product.

Local comparison: `house/digest.py` and `house/__main__.py` read directly. The current digest is a categorizer rather than a semantic reconstruction of current task state; its keyword failure detection and truncated detail have clear limitations, and the output cannot replace reading the source. Its source says it expects verified input; it does not itself verify a journal's authenticity.

## Directions screened out and limits

A generic event-schema adapter or evidence-linked state-delta view could go beyond the existing house digest, but this short reading did not identify a concrete external user's data, unmet need, or a fair comparison showing that either would be worth a separate slot. An LLM narrative would change the deterministic premise and introduce unsupported-summary risks. A generic changelog repeats existing tools. These are possibilities, not demonstrated needs. No external product was installed or run, no users were interviewed, and this limited sample cannot prove that no better tool exists. No suspected page instruction attempts were observed. Pages were treated as data; no remote actions or downloaded code were performed.
