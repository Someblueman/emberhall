# PDF meaning after transformation: the missing comparison

Linnet, 21 November 2026. Research for `pdf-meaning-survives`, current brief
25899. Read-only web research; no downloaded code executed, dependencies added,
PDF fixtures built or engines benchmarked. This is a proposed research boundary,
not evidence that an implementation works or that every existing engine fails.

**Finding:** retain the operation-aware experiment, but correct the brief's
comparison set before selection. Existing projects already supply semantic
snapshots, tag-tree regression checks and expert-labelled accessibility data.
The remaining opportunity is an independent expected result for a specified
merge or split, with adversarial interaction cases and reusable assertions.
Whether that warrants a new library rather than contributions to those projects
is still an experiment, not an established novelty claim.

## What the opened sources establish

- [W3C PDF3](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF3) explains the
  distinction between visible layout, logical reading sequence and keyboard
  navigation. Its checks include assistive technology or an accessibility API.
  Preserving a tag count does not establish this behavior.
- [veraPDF validation](https://docs.verapdf.org/validation/) limits PDF/UA
  checking to machine-verifiable requirements. Its
  [corpus](https://github.com/veraPDF/veraPDF-corpus/blob/staging/README.md)
  contains atomic, self-documented conformance examples, with CC BY 4.0 terms.
  Neither page establishes that operation-aware preservation tests are absent
  everywhere; they explain why another kind of expectation can matter.
- [qpdf issue 490](https://github.com/qpdf/qpdf/issues/490) is still marked open
  in the retrieved page. The 2020 report describes disappearing structure and
  alternative descriptions; the maintainer asks for redistributable examples
  or reproduction instructions. This is historical demand, not a run against
  today's version. The [pages plan](https://github.com/qpdf/qpdf/blob/main/TODO-pages.md)
  addresses preservation of document-level structures during assembly.
- [PDF Association techniques](https://pdfa.org/techniques-for-accessible-pdf/)
  supply minimal successful and failing examples. A new project must compare
  and credit them rather than announce the first meaningful PDF test corpus.
- [pdf-testkit](https://github.com/danmolitor/pdf-testkit) already offers an
  importable semantic regression library, snapshots and CI integration. Its
  README distinguishes authoritative producer layout from geometry-inferred
  raw-PDF structure, documents optional content-change detection, and deliberately
  ignores some reorderings. Thus neither “no semantic tests exist” nor “it cannot
  detect changed text” is defensible. Its documented contract does not itself
  establish a tagged reading-order, alternative-text and header-relation oracle
  for combining independent documents. That narrower comparison needs a trial.
- [LaTeX's tag-tree interpretation](https://github.com/latex3/tagging-project/discussions/789)
  models alternative text, replacement text, role mappings and attributes as XML;
  it also documents extraction limitations. The actual
  [l3build implementation](https://github.com/latex3/l3build/blob/main/l3build-check.lua)
  inserts `show-pdf-tags --xml` output in regression logs. A structural baseline
  and an extractor therefore already exist. Inspect and reuse these ideas before
  writing a parser. An [open replacement-text report](https://github.com/latex3/tagging-project/issues/1071)
  also warns that an extraction result is not an unquestionable semantic oracle.
- The [ASSETS 2025 benchmark paper](https://llwang.net/assets/pdf/2025_kumar_a11ybenchmark_assets.pdf)
  and [dataset](https://github.com/Anukriti12/PDF-Accessibility-Benchmark)
  already provide expert-labelled accessibility examples covering reading order,
  alternative text, tables and other criteria. They evaluate accessibility
  assessment, not the expected relation between inputs and an assembly result.
  The README's licence prose says MIT, while its linked licence is CC0; do not
  redistribute those documents on that conflicting summary. Original generated
  fixtures avoid this uncertainty, without implying they replace expert judgment.
- [PDFBox merger source](https://github.com/apache/pdfbox/blob/trunk/pdfbox/src/main/java/org/apache/pdfbox/multipdf/PDFMergerUtility.java)
  contains structure-tree, role-map and identifier-tree merging. Its optimized
  resource mode explicitly omits the structure tree; legacy mode attempts broader
  preservation. Record modes, not merely product names, in a comparison.
  [litho's published API](https://pkg.go.dev/github.com/gotenberg/litho/pkg/pdf)
  describes merged logical structure and split pruning. These are serious
  existing implementations; documentation alone neither passes nor fails them.

## The discriminating experiment if selected

1. Independently specify two original inputs with distinct paragraphs, image
   descriptions, heading roles and a two-page table wholly inside one chapter.
   Preserve input order and content multiplicity in the expected merged result.
   Include colliding custom role names and identifiers with different meanings.
2. Compare the simplest existing tag-tree snapshot approach with the proposed
   operation-aware assertions. Permit harmless object-number changes and correct
   role renaming; reject changed resolved roles, lost descriptions, wrong header
   targets, reordered logical text or missing/duplicated content. A byte-for-byte
   or raw XML equality test would reject legitimate transformations.
3. Keep the expected answer independent of the engine under test. A producer
   sidecar is useful input intent, but cannot prove the transformed PDF retained
   it. Calibrate the extraction path against known input intent and a second
   reading. Unsupported extraction must be explicit, never an empty passing tree.
4. Separate whole-document concatenation from chapter-aligned splitting. Check
   a whole-table retained chapter and a wholly excluded chapter. Defer arbitrary
   page fragments until the policy for incomplete paragraphs, tables and links
   is specified; a visual page cut alone does not define semantic preservation.
5. Use a deliberately altered, still structurally valid output to distinguish
   conformance from preservation. Also retain unchanged and harmless-renaming
   positive controls. Run one real engine in its documented mode before expansion.

By day three, stop if existing tools express the same contract with a small
fixture/configuration contribution, extraction cannot be calibrated independently,
or there is no reproducible distinction between conformance and the new checks.
Otherwise a multi-engine library with original interaction fixtures could merit
the proposed weeks. No implementation result was produced in this research run.
