## Candidate

**What a Reversible Floating-Point Sum Must Remember.** A short scientific
note with a runnable exact-arithmetic checker would test the addition rule
in Dwarka's *Towards energy-efficient scientific computing* (2026), derive
an explicit information-retention bound for that rule, and trace its
consequence through one tiny matrix accumulation.

The question is whether a two-word accumulator preserves its previous
state, with the other operand retained. That is stronger than a small
numerical error. The proposed work must distinguish a local overwrite from
a complete computation that retains its inputs. It must not infer that
reversible numerical computation is impossible, or estimate hardware energy.

The paper's section 2.4.1 states an addition rule on pairs satisfying
`abs(low) <= 2^-53 * abs(high)`. Section 5 reports nonzero reverse errors;
these do not by themselves establish a collision, and its later qualification
about ideal arithmetic must be represented fairly. Algorithm 4 specifies an
accumulate-and-subtract reverse pass. These give a concrete, checkable target.

A feasibility lead, not yet a checked result: keep `(1, 2^-54)` fixed and
compare small distinct accumulators with zero low words. The low-word
rounding may swallow their difference, without subnormal or nonfinite
arithmetic. A builder should derive a family in
precision `p`, show that all members satisfy the stated representation,
and count how much distinguishing state an inverse would require. Do not
substitute the easy observation that a four-word input has a two-word output
for the stronger fixed-operand test.

A one-off feasibility calculation evaluated that displayed addition
expression with Python binary64 additions and an exact rational residual
for each specified TwoSum. Both `(0, 0)` and `(2^-163, 0)`, added to the
same `(1, 2^-54)`, returned `(1, 2^-54)`. Their exact sums differ by
`2^-163`; both input pairs satisfy the stated bound. This is a promising
specific witness, not an independently checked transcription or a run of
the author's implementation. The parameterized family, information bound
and matrix example remain work for the selected project.

Freeze the proposed family before building: for precision `p >= 3`, use
the addend `(1, 2^(-p-1))` and accumulators
`(j * 2^(-3p-4), 0)` for `0 <= j < 2^p`, assuming an exponent range
containing these nonzero values. The intended result is one common output
and hence a `p`-bit lower bound on distinguishing information for this
family. The one-off binary64 probe above checks only `p=53, j=0,1`.
If the family or its interpretation fails, do not silently switch to a
different arithmetic primitive.

## Acceptance proposed before building

One person derives and implements the exact published rule with each
rounding operation explicit. Another independently reconstructs the
arithmetic and the counting argument. Deliver a paper, a dependency-free
command, a recorded run, a valid binary64 collision if one exists, and a
small matrix example using the stated order. Include an exact case that
does reverse and a control that retains the distinguishing information.
Acceptance requires agreement on input validity, bit patterns, retained
state and scope. Drop if the suspected collision violates the actual
contract, if an existing result already answers this exact target, or if
the result amounts only to a rounding-error demonstration without a
newly useful conclusion about the stated reversibility claim.

2. [Ogita, Rump and Oishi, Accurate Sum and Dot Product](https://www.tuhh.de/ti3/paper/rump/OgRuOi05.pdf).
   Algorithms 3.1–3.5 and Theorem 3.4 distinguish exact residual identities
   from an inverse that recovers the operands; cascaded residual addition
   itself rounds. Their work already supplies the numerical techniques.
3. [Bennett, Logical Reversibility of Computation](https://www.dna.caltech.edu/courses/cs191/paperscs191/bennett1973.pdf).
   Introduction and the forward/copy/uncompute construction. Keeping input
   and temporary history matters; an output-only dimension argument is not
   a criticism of Bennett's construction.
4. [Joldes, Muller and Popescu, Tight and Rigorous Error Bounds](https://www.researchgate.net/publication/320313271_Tight_and_Rigorous_Error_Bounds_for_Basic_Building_Blocks_of_Double-Word_Arithmetic).
   Author-uploaded full text, definition of a double-word number and
   Algorithms 4–6. Accurate two-word addition already has nonzero error
   bounds and constructed difficult cases. Do not claim to discover that
   double-word arithmetic rounds.
5. [Muller and Rideau, formalization abstract](https://www.researchgate.net/publication/354326936_Formalization_of_double-word_arithmetic_and_comments_on_Tight_and_rigorous_error_bounds_for_basic_building_blocks_of_double-word_arithmetic).
   Abstract only; full text unavailable there. Reports a formal check and
   improved bounds for the earlier work. HAL routes were blocked. No Coq
   build was attempted.
6. [Zhang and Aiken, Automatic Verification of Floating-Point Accumulation Networks](https://theory.stanford.edu/~aiken/publications/papers/cav25.pdf).
   Introduction and verification scope. Existing work proves accuracy and
   nonoverlap properties and supplies a better two-word addition algorithm.
   This proposal must not become a replacement verification tool or claim
   those numerical bounds as new.
7. [NiLang paper, under-review version](https://openreview.net/references/pdf?id=Yjo2qR0Pxm),
   section 3.1, and [the language's own documentation](https://giggleliu.github.io/NiLang.jl/dev/).
   The paper explicitly treats floating-point reversal as approximate.
   An exactness-versus-accuracy distinction is established prior knowledge,
   not itself this proposed contribution.
8. [Frank, Generalized Reversible Computing](https://www.sandia.gov/app/uploads/sites/210/2022/06/grc-arxiv-v3.pdf).
   Abstract, definitions of conditioned operations and Theorem 6. An
   operation can be reversible on its supported initial states without
   being reversible on every representable state. Check the actual
   precondition and retained state; a collision outside that support would
   not refute the conditioned operation. This is another reason to exclude
   hardware-energy conclusions from the proposed arithmetic result.
