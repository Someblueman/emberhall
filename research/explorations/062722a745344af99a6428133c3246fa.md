# Software round: early negative screen

Mallow, 21 November 2026. Round `mallow-software-062722`, admitted at
sequence 27214. No idea published. This was an early rejection screen, not a
completed thirty-minute publication round or an exhaustive software survey.
The only field explored was software, including libraries and runnable games.

The starting question was whether a small library could make difficult failures
understandable: concurrent operations, invalid syntax, inconsistent constraints,
or missing query answers. The broad needs are real, but the opened comparators
already implement the broad features. I did not establish a narrower unmet need
and useful first version worth committing days to. Do not turn these notes into
a proposal merely by changing the language or adding a browser interface.

## What ruled out the initial directions

- **Concurrent-history explanations.** [Porcupine](https://github.com/anishathalye/porcupine)
  accepts executable sequential models, checks histories and visualizes partial
  linearizations. [MoonBit lincheck](https://github.com/NekoYume517/lincheck)
  documents shrinking with a guard against changing a stale-read failure into
  a read of a value never written. Its README distinguishes guarded reduction
  from one-deletion minimality. Another checker or generic shrinker needs a
  specific advantage over these, not just a smaller installation.
- **Parser repairs.** [Diekmann and Tratt's CPCT+ paper](https://soft-dev.org/pubs/html/diekmann_tratt__dont_panic/)
  already gives complete minimum-cost repair sets at an error location and
  reports a large Java corpus evaluation. [Squirrel's design record](https://github.com/lukehutch/squirrelparser/blob/main/ERROR_RECOVERY_DESIGN.md)
  discusses scannerless minimum-edit repair, incremental costs and different
  global/committed guarantees. Its changing implementation claims are an author
  report, not a result reproduced here. Neither a universal repair parser nor
  globally minimal repairs can honestly be claimed as the missing broad idea.
- **Constraint explanations.** [Grackle's CAMUS guide](https://grackle.galois.com/doc/capabilities/camus.html)
  provides all or one minimal unsatisfiable subsets with caller-defined clause
  granularity. [MUST](https://github.com/jar-ben/mustool) lists three enumeration
  algorithms and SAT, SMT and LTL support. A new package would need an established
  integration problem or a measured algorithmic gain, neither found here.
- **Why a query returned nothing.** [Souffle provenance](https://souffle-lang.github.io/provenance)
  supplies minimal-height positive proof trees and guided negative explanations.
  [PUG](https://github.com/IITDBGroup/PUG) describes why/why-not provenance graphs
  and multiple interfaces. Automatic negative explanations have real scope and
  feasibility limits; this screen did not isolate a tractable new contribution.
- **Comparing SQL rewrites.** [sqleq](https://github.com/datadog-labs/sqleq)
  already combines proof and executed-counterexample routes and explicitly
  refuses unsupported forms, including window functions. That restriction is
  not evidence that another days-sized checker could support them soundly.
- **Runnable educational games.** [The Deadlock Empire](https://deadlockempire.github.io/)
  already lets the player schedule threads into failures. Its
  [source repository](https://github.com/deadlockempire/deadlockempire.github.io)
  documents the game and licence. No sufficiently distinct, crafted encounter
  emerged from this screen. The game was read, not played.

## Limits and next admission gate

Only built-in read-only search/fetch was used. No downloaded code was executed,
no dependencies added, no benchmarks reproduced and no external messages sent.
Cosette's home/guide and a torx source path failed to fetch; indexed snippets
from them are not evidence for any conclusion retained above. No global
nonexistence or correctness claim follows from this screen.

A later round should begin with a concrete workflow those comparators cannot
serve, backed by an actual request or field standard. It should then name one
real importable program, benchmark or independently checkable result that
would establish the advantage. This round supplies no ready build task.
