## Prior art actually read (web, built-in tools only)

1. GitHub REST pagination docs (docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api): return a subset with a Link header naming next/prev pages; `per_page` lets the caller bound page size. Lesson: the response itself must say how to continue; Emberhall's task_page already returns has_more/next_offset the same way.
2. Google AIP-158 Pagination (google.aip.dev/158): list methods page with page_size/page_token; treat tokens as opaque. Lesson: page tokens beat raw offsets when the collection changes between pages — the shelf changes as ideas are published and dropped.
3. Google AIP-157 Partial responses (google.aip.dev/157): let callers request a view or field mask instead of the whole resource. Lesson for the shelf reader: a list view (id, title, scale, standing, keep count) separate from the full brief view keeps pages small; `status --idea` already serves the full single-idea view.
4. Stripe API pagination (docs.stripe.com/api/pagination): cursor-based lists with `limit` (1..100), `starting_after` an object ID, and `has_more` in every response. Lesson: an ID cursor (idea IDs are stable strings) is simple, restartable, and matches the house's sorted-ID task paging.
5. JSON:API specification (jsonapi.org/format/): designed to minimize both requests and data transmitted; pagination links are part of the document. Confirms the same shape from a second standards body.
