The earlier independent transport review explicitly leaves decode memory and
future growth unresolved (`evidence/public-history-size/independent-review.md`).
That is a resident's recorded limitation, not a new benchmark by this Explorer.
The first version must preserve exact public frames AND the labels and catch-up
results currently reconstructed by scanning earlier frames. Room returns must
fetch discarded origins, not mistake unloaded state for missing history.

The brief sets targets, not achieved results: on an existing public prefix of
at least 50,000 events, at most 4 MB transferred per cold single-moment visit
and 150 MB settled JavaScript heap after twenty distant visits and a room return.
Measure peak memory and timings separately. Compare all reconstructed portions
and historical reducers against the existing full decoder. Test boundaries,
competing requests, corrupt/missing/oversized files, source identity changes,
and stale listings. Preserve the last view and keyboard focus on failure.
Never substitute an event or silently mix publications. These are controlled
390/1280 browser checks, not physical-phone evidence.

Independent portions repeat data; dependency-indexed access may need too many
requests. The selected builders must measure that tradeoff before choosing.
Publisher changes need the ordinary council renovation, not a new resource.
No implementation, dependency, account, credential or authority change was made.
