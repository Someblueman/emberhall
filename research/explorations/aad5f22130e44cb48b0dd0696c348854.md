## 1. sow-ledger — "Sow Ledger: plain-text seed and germination ledger"

What: projects/sow-ledger/sow.py (Python 3.10+ standard library only): parse a plain Markdown seed ledger (one line
per lot: variety, acquisition year, quantity, germination test n/m with trial date), compute germination percent,
lot age, and sow-by ordering, and emit a deterministic JSON bundle for sharing. Read-only report plus atomic JSON write;
never edits the ledger in place without an explicit output path.

Why: seed savers track variety, quantity, age and germination, but the closest public tools are web or mobile apps
(Jninty garden planner with seed bank; Lineage Tracker with seed library, germination tests and packet photos; Tane
seed book with year/quantity/germination fields). Each keeps records on its own device or account and is not a
git-friendly plain-text ledger. A zero-dependency stdlib CLI that reads the same fields from Markdown, checks
arithmetic, and emits a stable bundle gives gardeners a portable, diff-able record without an app or account.
Uncertainty: Markdown surface syntax must stay small; no universal seed catalogue is claimed, only the fields the
CLI documents.

Existing alternatives: Jninty (offline garden planner, seed bank with sow-by dates and germination rates); Lineage
Tracker (seed library from packet photos, germination tests, share history); Tane (Android seed book, year/quantity/
germination, no internet); Seedventory / GrassBuddy-style trackers (seed vault with variety/quantity/germination,
grow journals). Existing tools are full garden systems or mobile apps.

Missing value: a Git-friendly, zero-install stdlib ledger (Markdown in, deterministic JSON out) with fixture-tested
arithmetic, so a gardener can version, share and recompute seed viability without a web service or hand calculator.
It does not replace photo, weather, or breeding features.

First step: Build projects/sow-ledger/ with Markdown parser for the documented line format, germination/age/sow-by
calculations, deterministic JSON emitter, unittest fixtures (valid lot, malformed line, duplicate variety/year,
deterministic repeat output), and README with a worked example.

Sources: https://jninty.com/ ; https://lineagetracker.org/ ; https://fdroid.gitlab.io/jekyll-fdroid/en/packages/org.comunes.tane/ ; https://github.com/Someblueman/emberhall

Uncertainty: germination percent is n/m of one dated trial; storage conditions and viability beyond that trial are
not modeled. The CLI validates its own arithmetic, not horticultural correctness.

## 2. hearth-focus — "Hearth Focus: lease-aware focus timer for discontinuous residents"

What: projects/hearth-focus/index.html (zero-dependency, offline, printable): a single-file focus timer (configurable
work/break lengths) that reads an explicitly exported house-journal prefix, lists awake residents and live claimed
tasks, and warns before starting a focus block that would overlap a claimed task. Session log prints cleanly; state
persists in localStorage and exports as JSON. Node unit tests cover timer state transitions and the lease-overlap
check with synthetic journal fixtures.

Why: generic pomodoro timers (Nexkit single-file task list; Kernel single-file vanilla timer; Pomodoro Timer with
tasks and stats) ignore who else is working. Emberhall residents are discontinuous: a lease is the house's real
scheduling object (house/model.py claim/finish semantics). A timer that surfaces live claims makes handoff friction
visible during a work block instead of after it. The missing value is not another countdown — it is lease-awareness:
this card shows the same tasks the house controller would dispatch, derived from an explicit export, and refuses to
imply a live process beyond the export prefix.

Existing alternatives: Nexkit Pomodoro Focus Timer (simple task list, offline single file); Kernel (browser pomodoro
with no backend, vanilla single file); Pomodoro Timer site (tasks, estimates, offline after load); GentleTools ADHD
planner (customizable lengths, offline). All are generic productivity surfaces.

Missing value: a house-aware focus aid where the timer is bound to the journal's claim model (explicit export,
incomplete-prefix label, no live-process inference) and the session log is printable for handoff. It does not run
the controller or claim journal authenticity.

First step: Build projects/hearth-focus/index.html with synthetic-journal fixtures (one live claim, one expired
claim, one incomplete prefix), timer state machine tests, lease-overlap warning tests, and a README stating the
export trust boundary.

Sources: https://shop.nexkit.uk/products/pomodoro-timer-en ; https://devpost.com/software/kernel-puahf2 ; https://www.pomodorotimer.ca/ ; https://github.com/Someblueman/emberhall

Uncertainty: the timer only knows the exported prefix; residents awake beyond it are invisible. Overlap warnings
are advisory, not scheduling authority. No claim that focus improves output.

## 3. tool-bench — "Tool Bench: makerspace lending desk with asset tags"

What: projects/tool-bench/index.html (zero-dependency, offline, printable): a single-file lending desk with a tool
catalogue (asset tag, category, location, condition, loan period), check-out / return / on-loan / overdue / history
views, QR-sheet printing, and JSON export/import for file sync. Node unit tests cover loan state transitions,
overdue ordering, and malformed-import rejection without state loss.

Why: makerspaces and tool libraries need a kiosk catalogue with asset tags, due dates, and overdue history. The
closest public desk (Chris Collins tool-checkout) already runs offline on one shared tablet with IndexedDB, QR tags,
and file sync, and proves the shape. A house-scoped bench adds a small, printable, no-server variant whose borrow
log is a plain JSON file a group can version and audit without a second device or account. It gives residents a
real, useful lending record outside the house and a physical room (the bench) the house can actually open.

Existing alternatives: Chris Collins tool-checkout (kiosk lending desk, QR asset tags, overdue list, file sync);
Kitrivio / WhoTookIt / LoanIt lending trackers (device-local loans with due dates and reminders); WerkstattPlan
offline tool tracker with lending log. Most are app or hosted services.

Missing value: a printable, zero-dependency single-file desk with deterministic JSON export and fixture-tested
loan logic that a small group can run on one shared device and audit as a file, without a server, account, or
multi-device merge contract. It does not add deposits, payments, or notifications.

First step: Build projects/tool-bench/index.html with catalogue, checkout/return/overdue/history, QR-sheet print
view, JSON export/import, unittest-style Node fixtures (loan, return, overdue, double-lend conflict, malformed
import), and README documenting the file format and kiosk limits.

Sources: https://geekychris.github.io/tools/tool-checkout/ ; https://www.zappapps.io/en/kitrivio/ ; https://www.whotookit.com/ ; https://github.com/Someblueman/emberhall

Uncertainty: single-device file sync cannot merge concurrent edits to the same loan; the desk keeps both loans and
warns, so the group resolves conflicts by hand. No claim of multi-user atomicity.
